5. HERO VIDEO - THE BOOMERANG PIPELINE
===============================================================================

The original 4K60 24Mbps clip caused heavy scroll lag (decoding competed with
Lenis, GSAP and WebGL for the main thread). It was replaced by a TRUE
PALINDROME file that plays forward forever with the native `loop` attribute
and never seeks.

Source: 3840x2160, 60fps, 900 frames, 15s, 24.4 Mbps, h264+aac, 45.7 MB
Output: 1920x1080, 30fps, 899 frames, 29.97s, 2.05 Mbps, no audio, 7.7 MB

  1. ffmpeg -i hero-source.mp4 -an -vf "scale=1920:-2,fps=30" -c:v libx264
       -crf 24 -preset medium -g 30 -keyint_min 30 -sc_threshold 0
       -pix_fmt yuv420p -movflags +faststart hero-fwd.mp4
  2. ffmpeg -i hero-fwd.mp4 -an -vf "reverse,trim=start_frame=1,
       setpts=PTS-STARTPTS" ... hero-rev.mp4
  3. ffmpeg -f concat -safe 0 -i list.txt -c copy -movflags +faststart
       hero-boomerang-1080.mp4

Scale BEFORE reversing (the reverse filter buffers frames in RAM).
trim=start_frame=1 drops the duplicated turnaround frame so the loop doesn't
hitch. 720p variant: -vf "scale=1280:-2" -crf 26. Poster: -frames:v 1 -q:v 4.

ffmpeg 8.1.1 is at:
  C:\Users\Laptop Click\AppData\Local\Microsoft\WinGet\Packages\
  Gyan.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\
  ffmpeg-8.1.1-full_build\bin\ffmpeg.exe

NEVER point HERO_VIDEO at the raw Dropbox 4K original - it reintroduces the
lag and won't loop seamlessly.

6. PERFORMANCE - WHAT WAS TUNED AND WHY
===============================================================================

All of these were deliberate fixes for user-reported scroll lag. Do not
revert without a reason:

* Hero video: 4K60 -> pre-baked 1080p30 boomerang, audio stripped.
* useVideoPlayback: pauses when off-screen or tab hidden.
* dither/gl/scene.js: renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5))
  - was 2. ~44% less pixel work across the post, trail and cardbuffer passes.
  Safe because dithering destroys fine detail anyway.
* DitherCarousel WAKE_MARGIN: '50% 0px 50% 0px' - was '100% ...', which woke
  the GL loop a full viewport early, i.e. during the intro section, which is
  exactly where the lag was felt.
* Portrait image: Cloudinary w_640,q_auto,f_auto + width/height +
  loading="lazy" + decoding="async". It was previously a full-size PNG
  rendered into a 320px box.
* Engine already had antialias: false and powerPreference: "high-performance".

ALWAYS benchmark with `npm run build && npm start`. Dev mode is not
representative - it recompiles on navigation and inflates jank.

Next lever if jank ever returns: the DitherCarousel ScrollTrigger pin
(pinType: 'transform', anticipatePin: 1, refreshPriority: 1).

7. KNOWN NON-ISSUES (do not "fix" these)
===============================================================================

HYDRATION ERROR: "A tree hydrated but some attributes of the server rendered
HTML didn't match..." pointing at layout.tsx <body>.
CAUSE: The Bitdefender browser extension injects bis_status="ok",
bis_frame_id="...", bis_skin_checked="1" and __processed_<uuid>__="true"
onto elements before React hydrates. `bis_` = Bitdefender Internet Security.
It is NOT a code bug. Confirm by loading in incognito with extensions
disabled. Dev-overlay only; never appears in production.
(This was misdiagnosed twice as a RevealLoader inline-<style> problem. It
was the extension all along.)

INTRO REPLAYS ON EVERY RELOAD: intentional and faithful to the original -
RevealLoader clears sessionStorage 'intro_played' on mount. Can be made
once-per-session on request.

gsap.registerPlugin(ScrollTrigger) is called in both SmoothScrollProvider
and HomeShell. Idempotent and harmless.

12. ENVIRONMENT / TOOLING QUIRKS (VS Code MCP bridge)
===============================================================================

These cost real debugging time. Read before running commands.

* NEVER parallelize bridge calls - concurrent calls kill the tunnel. One at a
  time, always.
* run_terminal_command TIMEOUTS ARE LIARS. The command usually DID run.
  Always verify state before re-running (check dev.log, probe the port).
* Default shell is cmd, NOT PowerShell. `Get-ChildItem` fails with exitCode
  255. Use `powershell -NoProfile -Command "..."` explicitly.
* spawn_terminal is BROKEN here - returns an id but the terminal is dead.
  Use a detached start instead:
    start "nextdev" /D "D:\website\nextjs-site" cmd /c "npm run dev > dev.log 2>&1"
* `type <file>` prints nothing / truncates on multi-file batches. Write probe
  output to a file with Out-File -Encoding ascii, then read_file it.
* PowerShell probes return empty stdout - always follow with read_file.
* Complex inline PowerShell through cmd is quoting-hostile. For multi-edit
  patches, create_file a .ps1 and run it with
  `powershell -NoProfile -ExecutionPolicy Bypass -File`.
* write_file can SILENTLY not persist on an already-corrupt file (returns
  bytesWritten but disk stays NUL). Workaround: delete, then create_file,
  then verify the byte count.
* Always write UTF-8 WITHOUT BOM. A BOM/NUL corruption once produced
  "Unexpected character '\0'" build failures.
* Avoid scratch files named nul.txt (reserved Windows device name).
* Never let compressed-URL placeholders leak into generated source.

Useful commands:
  Restart clean:
    taskkill /F /IM node.exe >nul 2>&1 & ping -n 4 127.0.0.1 >nul &
    rmdir /s /q .next 2>nul & start "nextdev" /D "D:\website\nextjs-site"
    cmd /c "npm run dev > dev.log 2>&1"
  Type check:  npx tsc --noEmit > tscheck.txt 2>&1
  Port check:  netstat -ano | findstr LISTENING | findstr :3000
  Text search: findstr /s /i /n /c:"pattern" *.ts *.tsx *.js
  A corrupt .next causes a 500 with "Unexpected end of JSON input" ->
    rmdir /s /q .next and restart.

Dev server: http://localhost:3000 (LAN: http://192.168.68.105:3000)

13. AI STUDIO MIGRATION - HOW IT WAS DONE
===============================================================================

Goal: get the local Next.js app into Google AI Studio without letting the
model rewrite it. All 45 files landed successfully.

What worked:
1. A "passive host" first prompt. These platforms ALWAYS scaffold on turn one,
   so aim that turn rather than trying to forbid it: have it create only
   package.json / tsconfig.json / next.config.ts / postcss.config.mjs with
   exact dependency pins, plus standing rules and an ACK protocol
   ("RECEIVED: <path> (<line count> lines)").
2. A scaffolding prompt creating an EMPTY .gitkeep in each folder. Empty
   folders cannot persist otherwise. .gitkeep is inert - TypeScript, ESLint
   and the router all ignore it, so there's nothing for the model to "fix".
   Capitalisation matters: public/Fonts, not public/fonts.
3. Files added via the File explorer's + icon, typing the FULL relative path
   (parent folders are created implicitly), then pasting from VS Code.
   NEVER attach code files to the chat - the model retypes and truncates them.
4. Verify each paste by comparing the editor's line count to the local file.
   This is the truncation detector.
5. Drop order: leaf-first, entry points last (lib/config -> styles ->
   gl/shaders -> gl -> hooks -> leaf components -> section components ->
   SmoothScrollProvider, HomeShell, layout.tsx, page.tsx).

Traps: do NOT click the "Fix" button or the "Add global CSS" / "Setup root
layout" chips - errors are EXPECTED until layout.tsx and page.tsx land, and
Fix invents files instead of repairing references.

Video files are too large to paste. Either drag the binaries into
public/video/ or host them and update src/config/media.ts - the only file
that references video paths. Note remotePatterns in next.config.ts governs
next/image only, not the <video> tag.
